Project WoogleNet: Network Infrastructure Documentation

This repository contains the architectural design, hardware inventory, and deployment walkthrough for the WoogleNet home environment.
🌐 Network Architecture
Current State

    Primary Subnet: 10.0.0.1 / 255.255.0.0
    Wireless: Two isolated SSIDs (WoogleNet and `WoogleNetDMZ**

Future State (Target Configuration)

To achieve the goal of three distinct but communicating production networks, the environment will move to a VLAN-based architecture.
1. Production Environment (10.0.x.x)

Communication is permitted between these three VLANs.
Network	VLAN	IP Range	Purpose	Assignment
Network 1	10	10.0.1.1 - 10.0.1.10	Management/HW	Static (Router, Switches, APs)
Network 2	2**	10.0.2.10 - 10.0.2.99	Servers/Services	Static (TrueNAS) / Mixed (VMs/Containers)
Network 3	30	10.0.3.100 - 10.0.3.254	Personal Devices	DHCP (Phones, Laptops, Desktops)

    Wireless Access: WoogleNet (2.5GHz & 5GHz) →→ Maps to VLAN 30.

2. IoT Environment (192.168.1.x)

    Subnet: 192.168.1.1/24
    Access: DHCP.
    Security: Internet-only; no routing permitted to Production, Guest, or Management networks.
    Wireless Access: WoogleNetIOT.

3. Guest/DMZ Environment (192.168.2.x)

    Subnet: 192.168.2.1/24
    Access: DHCP.
    Security: Internet-only.
    Wireless Access: WoogleNetGuest.

📦 Docker on Ubuntu Setup
Manual Installation Steps

    Update the existing system packages.
    Install prerequisite packages to allow apt to use a repository over HTTPS.
    Add the official Docker GPG key for package verification.
    Set up the stable Docker repository.
    Install Docker Engine, CLI, and Docker Compose.
    Add the current user to the docker group to avoid using sudo for every command.

Automation Script

Save the following as setup-docker.sh, make it executable with chmod +x setup-docker.sh, and run it as root.
bash

#!/bin/bash

# WoogleNet Docker Installation Script for Ubuntu
# Run as root or with sudo

set -e

echo "Updating system packages..."
apt-get update && apt-get upgrade -y

echo "Installing prerequisites..."
apt-get install -y ca-certificates curl gnupg lsb-release

echo "Adding Docker GPG key..."
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg

echo "Setting up Docker repository..."
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  tee /etc/apt/sources.list.d/docker.list > /dev/null

echo "Installing Docker Engine and Compose..."
apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

echo "Configuring permissions for current user..."
# Gets the user who called sudo
SUDO_USER=${SUDO_USER:-$(whoami)}
usermod -aG docker $SUDO_USER

echo "Installation complete. Please log out and back in for group changes to take effect."
docker --version
docker compose version

🚀 Setup Walkthrough
Phase 1: Gateway & VLAN Core

    Provision UCG-Fiber: Set up the primary gateway and configure the WAN interface.
    Define VLANs:
        Create VLAN 10 (Mgmt), 20 (Servers), 30 (Personal).
        Create separate subnets for IoT (192.168.1.1) and Guest (192.168.2.1).
    Firewall Rules:
        Allow inter-VLAN routing for VLANs 10, 20, and 30.
        Implement "Drop" rules for IoT and Guest VLANs to prevent access to any internal 10.0.x.x addresses.

Phase 2: Switching & Wireless

    Switch Adoption: Adopt all UBNT and TPLINK switches.
    Port Assignment: Assign ports to specific VLANs based on the connected device (e.g., Server ports →→ VLAN 20).
    Wireless SSID Mapping:
        WoogleNet →→ VLAN 30
        WoogleNetIOT →→ IoT Subnet
        WoogleNetGuest →→ Guest Subnet
    AP Placement: Deploy APs to designated locations (Attic, Basement, Living Room, Office, Game Room, Backyard**

Phase 3: Compute & Services

    Hardware Install: Mount Dell R720s in U24-U31.
    TrueNAS Deploy: Install TrueNAS on all 4 nodes. Assign static IPs within the 10.0.2.x range.
    Ubuntu Host Setup:
        Provision Ubuntu VMs on TrueNAS nodes.
        Run the setup-docker.sh script to prepare container environments.
    Service Deployment:
        Deploy VMs (AD, Proxy, Web, DL).
        Deploy Containers according to the naming convention (e.g., DAXPlex).
    Verification: Ensure the Proxy VM can route traffic to the containerized services.

Phase 4: Client Onboarding

    Personal Devices: Connect devices to WoogleNet and verify DHCP assignment in the 10.0.3.x range.
    IoT Devices: Connect to WoogleNetIOT and verify they cannot ping the TrueNAS nodes.
    Guest Access: Verify WoogleNetGuest provides internet access only.**



The Integrated AI Strategy (The "Omni-AI" Stack)

To achieve all three goals (API, Smart Home, and Knowledge Base), we will implement a layered approach.

1. The Engine (Ollama + GPU Allocation)

    Implementation: Ollama will serve as the core API provider.
    Hardware Split:
        RTX 3060: Dedicated to your primary LLMs (e.g., Llama 3 or Mistral) for general chat and RAG. Its VRAM is critical for the "thinking" part of the system.
        GTX 1070: Dedicated to smaller, specialized tasks, such as Whisper (Speech-to-Text) for Home Assistant or a dedicated stable diffusion instance if you add image generation.
    Result: You have a high-performance API that other containers can call without starving the primary LLM of memory.

2. The Interface (Open WebUI)

    Implementation: A Docker container acting as the frontend for Ollama.
    Role: This is where you interact with your AI. It supports multi-user accounts and allows you to switch between models hosted on different GPUs.

3. The Brain (Home Assistant Integration)

    Implementation: Connect Home Assistant to the Ollama API via the "Conversation" agent.
    Role: This allows you to use natural language to control your lab. For example, "AI, turn off the game server" or "AI, check if any containers are down in Uptime Kuma."

4. The Memory (RAG with BookStack)

    Implementation: Use a RAG (Retrieval-Augmented Generation) pipeline (likely via Open WebUI's built-in RAG or a separate tool like AnythingLLM).
    Role: You will point this at your BookStack documentation. When you ask the AI, "How did I set up the NFS shares on the Ubuntu VM?", the AI will search your BookStack pages first and provide an answer based on your actual documentation.

Critical Technical Note: The "Atomic Move" Requirement

Since you are using an ARR stack with NAS shares, we must ensure your Docker Compose files are written to support Atomic Moves (Hardlinks).

If you mount /data/downloads and /data/media as two separate shares, the system has to "copy and delete" files when moving them from downloads to the library. This causes massive disk I/O and doubles the space used during the move. To avoid this, we will structure your shares as one single root (e.g., /mnt/nas/data) with subfolders. I will ensure this is baked into the scripts.

Part 1: UDM-Pro Configuration Blueprint

Follow these steps in the UniFi Network Application. Since we are starting over, perform a factory reset on the UDM-Pro before beginning.
1. Global Network Settings

    WAN Setup: Configure your internet connection. Ensure "Smart Queues" are Off unless you have very slow internet (<100Mbps), as it can bottleneck your high-speed internal transfers.
    DNS: Set your WAN DNS to a reliable provider (e.g., 1.1.1.1 or 8.8.8.8). Later, we will point your internal clients to AdGuard Home.

2. VLAN Architecture (The Segmentation)

Create the following Networks in Settings →
→ Networks. This mirrors the intent in your Git documentation for a secure, organized lab.
VLAN ID	Network Name	Purpose	IP Range (Suggested)
1 (Default)	Management	UDM-Pro, Proxmox Host, Switches
10	Trusted/Main	Your primary PC, Laptops
20	Server/AI	Ubuntu VM, NAS, Docker Stack
30	IoT	Smart Home devices, Home Assistant
40	Guest	Isolated Internet access

3. Firewall Rules (The Security)

By default, the UDM-Pro allows all Inter-VLAN routing. To secure your lab, go to Settings →
→ Firewall & Security and create these rules in order:

    Rule 1 (Allow Established/Related): Allow State: Established and State: Related from any source to any destination. (This ensures that if you start a conversation with a server, the server can respond).
    Rule 2 (Allow Management): Allow Trusted (VLAN 10) to access Management (VLAN 1).
    Rule 3 (Allow Server Access): Allow Trusted (VLAN 10) to access Server (VLAN 20).
    Rule 4 (Block IoT to Everything): Block IoT (VLAN 30) from accessing all other internal VLANs.
    Rule 5 (Block Guest to Everything): Block Guest (VLAN 40) from accessing all other internal VLANs.


Part 2: Ubuntu Network Provisioning Script

While the UDM-Pro is manual, the Ubuntu Server VM is not. Since you are using Proxmox, ensure the VM network interface is set to Bridge mode and the VLAN tag is set to 20 in the Proxmox Hardware settings.

This script automates the configuration of a static IP, prepares your /etc/fstab for your NAS shares, and optimizes the network stack for high-throughput AI and Media traffic.

#!/bin/bash

# ==============================================================================
# WoogleNet Sprint 0: Ubuntu Network Provisioning Script
# This script configures Static IP (Netplan), NAS Mount points, and Sysctl tweaks.
# ==============================================================================

# --- CONFIGURATION ---
# Change these to match your actual network environment
INTERFACE="ens18" # Standard Proxmox virtio interface
STATIC_IP="192.168.20.10/24"
GATEWAY="192.168.20.1"
DNS_SERVERS="192.168.20.5, 1.1.1.1" # First IP should eventually be your AdGuard Home
HOSTNAME="wooglenet-server"

# NAS Shares (Adjust to your NAS IP and Share Names)
NAS_IP="192.168.20.50"
NFS_SHARE="/volume1/docker_data"
SMB_SHARE="nas_share"
SMB_USER="dockeruser"
SMB_PASS="yourpassword"

echo "Starting Network Provisioning for $HOSTNAME..."

# 1. Set Hostname
sudo hostnamectl set-hostname $HOSTNAME
echo "127.0.0.1 localhost" | sudo tee /etc/hosts
echo "$STATIC_IP $HOSTNAME" | sudo tee -a /etc/hosts

# 2. Configure Netplan (Static IP)
cat <<EOF | sudo tee /etc/netplan/01-netcfg.yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    $INTERFACE:
      addresses:
        - $STATIC_IP
      nameservers:
        addresses: [$DNS_SERVERS]
      routes:
        - to: default
          via: $GATEWAY
EOF

sudo netplan apply
echo "Network interfaces configured."

# 3. Prepare NAS Mount Points
echo "Preparing NAS mount points..."
sudo mkdir -p /mnt/nas/nfs
sudo mkdir -p /mnt/nas/smb

# 4. Update /etc/fstab for persistence
# We use 'nofail' so the server still boots if the NAS is offline
if ! grep -q "nas/nfs" /etc/fstab; then
    echo "$NAS_IP:$NFS_SHARE /mnt/nas/nfs nfs defaults,nofail 0 0" | sudo tee -a /etc/fstab
fi

if ! grep -q "nas/smb" /etc/fstab; then
    echo "//$NAS_IP/$SMB_SHARE /mnt/nas/smb cifs username=$SMB_USER,password=$SMB_PASS,iocharset=utf8,nofail 0 0" | sudo tee -a /etc/fstab
fi

sudo mount -a
echo "NAS shares mounted."

# 5. System Network Optimizations (Sysctl)
# Optimizing for high-volume data transfer (Media/AI models)
cat <<EOF | sudo tee /etc/sysctl.d/99-wooglenet-optimizations.conf
# Increase max open files
fs.file-max = 2097152
# Expand TCP window sizes for high-speed NAS transfers
net.core.rmem_max = 16777216
net.core.wmem_max = 16777216
net.ipv4.tcp_rmem = 4096 87380 16777216
net.ipv4.tcp_wmem = 4096 65536 16777216
# Allow faster recycling of TCP connections
net.ipv4.tcp_tw_reuse = 1
EOF

sudo sysctl --system
echo "Network optimizations applied."

echo "Sprint 0 Complete. Please reboot the server to ensure all changes persist."

How to use this script:

    Log into your Ubuntu Server VM.
    Create the file: nano setup_network.sh
    Paste the code above and edit the CONFIGURATION section with your actual IPs and NAS credentials.
    Make it executable: chmod +x setup_network.sh
    Run it: sudo ./setup_network.sh
